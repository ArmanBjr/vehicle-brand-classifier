## Phase 3 — Preprocessing

This is the most important part of the whole project.

The assignment explicitly asks for:

* missing data check
* duplicate detection/removal
* outlier detection/removal
* data type checking and encoding
* normalization/standardization of numerical features
* class imbalance checking and fixing if needed 

Do them in the following order.

### Step 3.1 — Separate features and target

In train set:

* `X = train_df.drop('Manufacturer', axis=1)`
* `y = train_df['Manufacturer']`

Test set has no label.

### Step 3.2 — Train/validation split

Do this **before** advanced preprocessing like SMOTE.

Use stratified split:

* 80% train
* 20% validation

Why:

* avoids leakage
* preserves class proportions

### Step 3.3 — Missing values

Check missing values in both train and test.

Then:

* if no missing values, explicitly state that
* if there are missing values:

  * numerical → median imputation
  * categorical → most frequent imputation

### Step 3.4 — Duplicates

Check duplicate rows in training set.

If duplicates exist:

* remove them from training only
* report how many were removed

Do not blindly remove duplicates from test.

### Step 3.5 — Outliers

For numerical columns:

* inspect distributions first using boxplots/histograms
* then decide whether to:

  * remove extreme outliers
  * or cap them

Better than deleting too much data:

* use IQR carefully only on selected columns
* or winsorize/cap extreme values

Important:
Do this only on training data statistics, then apply the same rule to validation/test if needed.

### Step 3.6 — Encoding categorical features

For columns like:

* transmission
* fuelType

Use:

* **OneHotEncoder** for features

For target:

* **LabelEncoder** for `Manufacturer`

### Step 3.7 — Scaling numerical features

For SVM, scaling is essential.
For Decision Tree, scaling is not necessary, but it is fine to keep a pipeline consistent.

Use:

* `StandardScaler` for numerical columns

### Step 3.8 — Class imbalance

Check the class distribution of `Manufacturer`.

If imbalance is noticeable:

* apply **SMOTE only on the training split**, never before splitting

This directly answers the assignment’s requirement to check whether classes are balanced and solve the issue if they are not. 

---

## Phase 4 — Build proper ML pipelines

Instead of manual preprocessing in separate loose steps, build pipelines.

### Recommended structure

For both models:

* preprocessing pipeline:

  * numeric → imputer + scaler
  * categorical → imputer + one-hot encoder

Then:

* model

For SVM:

* preprocessing + SMOTE + SVC

For Decision Tree:

* preprocessing + maybe SMOTE + DecisionTreeClassifier

Best practice:

* use `Pipeline`
* if using SMOTE inside workflow, use `imblearn.pipeline.Pipeline`

This keeps everything leakage-safe.

## Phase 6 — Hyperparameter tuning

Now improve both models.

The assignment explicitly requires hyperparameter tuning for both SVM and Decision Tree. 

### For SVM tune:

* `C`
* `kernel`
* `gamma`

Suggested grid:

* `C = [0.1, 1, 10, 100]`
* `kernel = ['linear', 'rbf']`
* `gamma = ['scale', 'auto', 0.01, 0.1, 1]`

### For Decision Tree tune:

* `criterion = ['gini', 'entropy']`
* `max_depth = [5, 10, 20, None]`
* `min_samples_split = [2, 5, 10, 20]`
* `min_samples_leaf = [1, 2, 5, 10]`
* maybe `max_features`

Use:

* `GridSearchCV` or `RandomizedSearchCV`
* scoring based on `f1_weighted` or `f1_macro`

I would not tune based only on accuracy.

## D. Treat outliers intelligently

A better project does not just blindly delete all IQR outliers.

### Better strategy

* inspect each numerical feature separately
* decide which columns deserve outlier handling
* distinguish:

  * rare but valid values
  * impossible/error values

Example:

* `year = 1970` may be unusual but not impossible
* `engineSize = 0` might deserve closer inspection
* extremely high `mpg` could be suspicious

### In the report

Explain why you removed or retained extreme values.

This kind of justification is exactly what makes a project look stronger.

---

## E. Use better metrics for multiclass imbalance

The assignment requires precision, recall, F1, confusion matrix. 

To go beyond minimum requirements, report:

* weighted precision / recall / F1
* macro precision / recall / F1
* accuracy

### Why this is stronger

* weighted scores show overall performance
* macro scores show whether minority classes are being ignored

Then say:

* “Although weighted F1 is high, macro F1 is lower, indicating weaker performance on some minority manufacturers.”

That is the kind of sentence that earns respect.

That kind of analysis makes the report much stronger.
